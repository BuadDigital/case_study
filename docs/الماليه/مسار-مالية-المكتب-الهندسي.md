# مسار مالية المكتب الهندسي

> **لمن؟** مشرف · أخصائي · مكتب هندسي · مالية · اختبار تشغيلي.  
> **ماذا؟** كيف تُستحق أتعاب الرفع، تُراجع، تُفوتر، وتُصرف — كـ **تكلفة / مورد** على الشركة، منفصلة عن **إيراد إنفاذ**.  
> **التصنيف في النظام:** `engineering-survey` · دور الطرف: `engineering-office`.

---

## 1) الفكرة بجملة

1. المكتب **ينجز الرفع** ويرسل المخرجات.  
2. المشرف/الأخصائي **يقبل المخرجات** → يُنشأ استحقاق أتعاب من **جدول التسعيرة**.  
3. إن وُجد **خصم**، المكتب يقبل أو يتحفّظ؛ الخلاف يُحل قبل المالية.  
4. المالية تبني **مسير / كشف فوترة** للطرف (مورد)، ثم **تُصدر**، المكتب **يرفع فاتورة ضريبية**، المالية **تطابق وتصرفه**.

| اتجاه الشركة | المعنى | المكتب؟ |
|--------------|--------|---------|
| **تكاليف (Outcome)** | أتعاب المكتب نظير الرفع | نعم — مورد |
| **إيراد (Income)** | فوترة إنفاذ | لا — ليس دور المكتب |

---

## 2) من يفعل ماذا؟

| الدور | حساب تجريبي (نمطي) | دوره |
|-------|---------------------|------|
| **مكتب هندسي** | `jeddah_survey` | رفع · قبول/تحفّظ خصم · رفع فاتورة على المسير |
| **مشرف** | `section-supervisor` | قبول مخرجات · خصم · حسم خلاف تسعير |
| **أخصائي** | `case-specialist` | متابعة تشغيلية · التسعيرة (عرض/تعديل حسب الصلاحية) |
| **مالية** | `financial-officer` | مسيرات التكاليف · مطابقة فاتورة · صرف/إغلاق |
| **مسؤول النظام** | CDO / إدارة | جداول التسعيرة والتحكم الكامل بالإعدادات |

---

## 3) الشاشات

| الدور | المسار | الاسم في الواجهة |
|-------|--------|------------------|
| مكتب / مشرف / أطراف | `/party-fees` | **فوترة الأتعاب** |
| مكتب | تبويبات داخل الشاشة | تتطلب إجراءكم · جاهزة للفوترة · كشوف الفوترة الصادرة |
| مشرف | نفس `/party-fees` → الأمور المالية | **قبول مخرجات الرفع** · خصم · متابعة إنفاذ |
| مالية | `/financial?area=costs` | **التكاليف** (المكتب كمستحق / vendor) |
| مالية (قديم/رابط مباشر) | `/financial?area=eng_portal` | بوابة المكتب (مسار URL) |
| إعدادات | `/fee-pricing` | **التسعيرة** — فئة «المكاتب الهندسية» |
| الجميع (حسب صلاحية) | تفصيل العقار → **المالية** | سطر أتعاب الرفع لنفس الصك |

عمل المكتب **اليومي** هو تقريباً كله على **`/party-fees`**.

## 4) دورة الحياة — خطوة بخطوة

```text
توزيع مهمة رفع مساحي
        ↓
المكتب يُكمل ويرسل المخرجات  (/active-survey/…)
        ↓
قبول المخرجات (مشرف/أخصائي)  →  استحقاق + سعر من جدول التسعيرة
        ↓
[اختياري] خصم مشرف → مكتب: قبول أو تحفّظ → حسم الخلاف
        ↓
جاهز للفوترة
        ↓
مالية: إنشاء مسير من المستحقات  (/financial?area=costs)
        ↓
مالية: إصدار المسير للمكتب
        ↓
المكتب: رفع فاتورة ضريبية (رقم + تاريخ + PDF)
        ↓
مالية: مطابقة / رفض الفاتورة
        ↓
مالية: إغلاق وصرف + إثبات دفع
        ↓
مفوتر / مدفوع  (KPI المكتب + تكاليف المالية)
```

### 4.1 استحقاق الأتعاب

| | |
|--|--|
| **متى؟** | عند **قبول مخرجات الرفع** — **ليس** عند إرسال الرفع وحده |
| **من أين المبلغ؟** | جدول تسعيرة الفئة `engineering-survey` (شرائح المساحة…) |
| **إعادة الرفع للتصحيح** | لا تنشئ أتعاباً جديدة |
| **أين يظهر القبول؟** | مشرف: `/party-fees` → قبول مخرجات الرفع المساحي |

إشعار النجاح (واحد): *قبول المخرجات — تم قبول مخرجات الرفع المساحي واستحقاق الأتعاب.*

### 4.2 التسعيرة

| | |
|--|--|
| **المسار** | إعدادات النظام → **التسعيرة** (`/fee-pricing`) |
| **الفئة** | المكاتب الهندسية (`engineering-survey`) |
| **من يعدّل؟** | مسؤول النظام · المشرف · الأخصائي (حسب الصلاحيات الحالية) |
| **محتوى الجدول** | شرائح المساحة (من/حتى م²) + الأتعاب · إسناد جداول للمكاتب · تعيين افتراضي |

بدون إسناد مكتب لجدول، قد لا يُحتسب التسعير لذلك المكتب كما يُتوقع.

### 4.3 الخصم والتحفّظ (إن وُجد)

| الحالة | من | إجراء |
|--------|-----|--------|
| خصم من المشرف | مشرف | تبويب الحسم والمراجعة |
| بانتظار إفادة المكتب | مكتب | **قبول** أو **تحفّظ** (سبب) |
| خلاف تسعير | مشرف ↔ مكتب | حسم قبل وصول البند للمالية |
| بدون خصم | — | يبقى جاهزاً وفق السعر بعد القبول/المسار |

### 4.4 من جهة المكتب — `/party-fees`

| التبويب / العنصر | الوظيفة |
|------------------|---------|
| KPI | مستحق غير مفوتر · بانتظار إفادتكم · جاهزة للفوترة · مفوترة/مدفوعة |
| تتطلب إجراءكم | قبول خصم / تحفّظ |
| جاهزة للفوترة | بنود جاهزة أو مرحَّلة |
| كشوف الفوترة الصادرة | مسيرات صدرت · رفع فاتورة على `issued` |

### 4.5 من جهة المالية — تكاليف المكتب

| الخطوة | القسم النموذجي | ماذا يحدث؟ |
|--------|----------------|------------|
| قائمة المستحقين | `costs` → الأطراف | يظهر **المكتب الهندسي** كـ vendor (+ ضريبة عند التطبيق) |
| المستحقات | `dues` | بنود جاهزة للادراج |
| إنشاء مسير | من البنود المختارة | مسودة كشف/مسير |
| إصدار | `statements` | يُرسل للمكتب لرفع الفاتورة |
| مطابقة فاتورة | بعد الرفع | قبول أو رفض |
| صرف وإغلاق | بعد المطابقة | إثبات دفع · الحالة `closed` / مدفوع |
| مدفوعة / مستبعدة | `paid` · `excluded` | أرشيف |

> مسار قديم باسم «أمر صرف من المكتب» لم يعد الأساس. المسار الحي: **مستحقات → مسير → فاتورة مورد → صرف**.

### 4.6 الإيراد — ليس للمكتب

| | |
|--|--|
| **فواتير إنفاذ** | `/financial?area=revenue` — دخل الشركة من إنفاذ |
| قد يتضمن بند «تكاليف الرفع» | كـ **إيراد على إنفاذ**، لا كصرف للمكتب |
| هامش تشغيلي تقريبي | إيراد إنفاذ − التزامات/صرف الأطراف (منها المكتب) |

## 5) حالات الدفع (بلغة بسيطة)

| ما تراه تقريباً | المعنى |
|-----------------|--------|
| مستحق / بعد القبول | نشأ الاستحقاق |
| بانتظار موافقة المكتب | خصم ينتظر إفادة |
| خلاف تسعير | تحفّظ قيد المعالجة |
| جاهز للفوترة | يمكن للمالية إدراجه في مسير |
| جاهز — مرحَّل | مؤجَّل لدورة لاحقة |
| مدرج / صادر (كشف) | داخل مسير |
| مفوتر / مدفوع | أُغلق وصُرف |

## 6) دليل اختبار وحدة بوحدة

### تشغيل

```powershell
# طرف 1
npm run dev:api

# طرف 2
npm run dev
```

تأكد أن F12 لا يظهر `ERR_CONNECTION_REFUSED` على المنفذ **5160**.

### السيناريو

| # | الدور | الإجراء | تحقق |
|---|-------|---------|------|
| 1 | مكتب | إكمال وإرسال الرفع | مهمة مكتملة / مرسلة |
| 2 | مشرف | قبول المخرجات من فوترة الأتعاب | إشعار قبول + اختفاء من قائمة الانتظار |
| 3 | مشرف (اختياري) | خصم بسب | يظهر عند المكتب «تتطلب إفادة» |
| 4 | مكتب | قبول أو تحفّظ | حالة جاهز أو خلاف |
| 5 | مشرف | حسم الخلاف إن وُجد | جاهز للفوترة |
| 6 | مالية | تكاليف → اختيار المكتب → مسير من المستحقات | مرجع مسير مسودة |
| 7 | مالية | إصدار المسير | حالة صادرة للمكتب |
| 8 | مكتب | رفع فاتورة (رقم + تاريخ + PDF) | فاتورة معلّقة على المسير |
| 9 | مالية | مطابقة → صرف/إغلاق | مدفوع |
| 10 | الكل | KPI مكتب + تبويب مالية العقار + التسعيرة للاحقة | اتساق الأرقام |
