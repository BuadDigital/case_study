# المرجع المنطقي — دور المالية

**الغرض:** الذاكرة الرسمية لمنطق المالية. يُنقل مع كل مشروع تصميم جديد، ويُحدَّث من واقع كورسر بعد كل تطبيق — لا من البروتوتايب.

**آخر تحديث:** 2026-08-04 · **مصدر الحقيقة:** كورسر (البروتوتايب مرجع تاريخي فقط)

---

## ١. القواعد الحاكمة

هذه قواعد لا تُخالَف عند تصميم أي إجراء جديد:

1. **النظام يسجّل ويتابع فقط.** الفواتير تُصدر من البرنامج المحاسبي الخارجي، وتُرفع على منصة إنفاذ. النظام يوثّق أرقامها ومرفقاتها.
2. **المالية لا تتعامل إلا مع أتعاب متفق عليها** بين المشرف والمكتب الهندسي. الخصومات والتحفّظات تُسوّى قبل الاستحقاق ولا تصل المالية.
3. **المورّد هو من يطالب.** المالية تُعدّ مسير الصرف، والمورّد يُصدر فاتورة مطابقة له ويرفعها. لا تُنشئ المالية مطالبة نيابةً عنه.
4. **قيمة الفاتورة محكومة بالمسير** ولا تُدخل يدوياً. المالية تُقر المطابقة أو تُعيد للتصحيح.
5. **الأفراد لا يُصدرون فواتير** ولا يلزمهم مسير — أمر صرف مباشر.
6. **لا صرف بلا إثبات:** سند صرف + مرجع تحويل + إيصال تحويل، الثلاثة إلزامية.
7. **أرقام إنجليزية** في كل المبالغ والمراجع والتواريخ. واجهة عربية RTL.
8. **الجداول:** العمود الأول وبياناته محاذاة لليمين، وبقية الأعمدة توسيط.
9. **مصطلحات محظورة داخل النظام:** «طابور» · «طرف/أطراف». البدائل: قائمة · المشاركون · الجهة · المستحقون.

## ٢. الكيانات

### 2.1 معاملة إيراد (`REV_TX`)
| الحقل | المعنى |
|---|---|
| `po` | رقم أمر العمل (للعرض والتجميع فقط) |
| `deed` | رقم الصك |
| `city` | المدينة |
| `status` | حالة الدورة الداخلية |
| `infath` | حالة المعاملة في منصة إنفاذ |
| `land` / `bld` | مساحة الأرض ومسطح البناء (من دراسة الحالة) |
| `valFee` | أتعاب التقييم — خاضعة للضريبة |
| `survFee` | أتعاب الرفع المساحي — خاضعة للضريبة، تُستحق فقط إن استحقها المكتب |
| `keyFee` | أتعاب استلام المفاتيح — **مبلغ ثابت شامل الضريبة** (عادة 250)، تُستحق فقط إن سُجّل مفتاح |
| `engDue` / `keyDue` | مؤشران: هل تستحق المعاملة أتعاب مكتب هندسي / مفاتيح — يأتيان من المعاملة نفسها |
| `inv` | `{no, date, uploadedAt}` بيانات الفاتورة |
| `pay` | `{date, amount, ref}` بيانات التحصيل |
| `followups[]` | `{date, channel, notes}` محاولات المطالبة |

**حساب الإجمالي:** `(valFee + survFee) + ضريبة 15% على مجموعهما + keyFee`
أتعاب المفاتيح لا تُضاف عليها ضريبة لأنها شاملة أصلاً.

### 2.2 بند تكلفة (`COST_LINES`)
| الحقل | المعنى |
|---|---|
| `payee` | المستحق |
| `list` → `amount` | سعر الجدول ← الصافي بعد التعديل |
| `ded` / `dedReason` | مقدار الخصم وسببه |
| `at` | تاريخ الاستحقاق (يُحسب منه العمر) |
| `taskRef` / `taskTitle` | مرجع المهمة — **للمراجع الحكومي ومنفّذي المهام** |
| `deed` / `po` | مرجع المعاملة — **للمكاتب الهندسية والمقيّمين** |
| `st` | `due` · `instmt` · `paid` · `excluded` |

**قاعدة المرجع:** الأتعاب المسندة بمهمة مرجعها المهمة، والمسندة بمعاملة مرجعها الصك. تُنقل مع البند إلى مستند الصرف.

### 2.3 مستند صرف (`COST_STMTS`)
| الحقل | المعنى |
|---|---|
| `ref` | مرجع المستند |
| `payee` / `ptype` | المستحق وصفته (`vendor` / `individual`) |
| `status` | حالة المستند |
| `period` | الشهر المالي (للمسيرات الآلية) |
| `lines[]` | بنوده — **تحمل `id` البند** للإقفال الدقيق |
| `vinv` | `{no, date, amount, file}` فاتورة المورّد |
| `rejected[]` | أرشيف الفواتير المعادة مع أسبابها |
| `inv` / `trf` / `receipt` / `paidAt` | إثباتات الصرف |
| `audit[]` | `{act, by, at}` سجل الإجراءات |

### 2.4 المستحق (`FIN_PARTIES`)
| الحقل | المعنى |
|---|---|
| `code` / `name` / `iban` / `phone` | الهوية |
| `role` | المهمة: مكتب هندسي · مراجع حكومي · مقيّم · معاين |
| `ptype` | `vendor` (منشأة تُصدر فواتير) أو `individual` (فرد) |
| `trackDues` | `false` = المتابعة معطّلة، تُدار أتعابه خارج النظام |

**مهم:** المستحق غير المتتبَّع يُعرض هويةً فقط — **بلا أرقام ولا أصفار**. الرصيد `null` لا `0`.

## ٣. دورة الإيرادات — فوترة مركز التصفية

```
تحت الدراسة → مؤهلة للفوترة → مساعد الفوترة → بانتظار التحصيل → محصّلة
                                   ↓
                              متوقفة ⇄ (تُستدعى وتُكمل)
                                   ↓
                              مستبعدة
```

| التبويب | المعنى | الإجراء |
|---|---|---|
| **تحت الدراسة** | لم تكتمل بعد | لا إجراء مالي |
| **مؤهلة للفوترة** | رُفعت على إنفاذ | تحديث حالة المعاملة (وداخله المطابقة) |
| **مساعد الفوترة** | طُوبِقت أتعابها | اختيار المعاملات وتسجيل فاتورة لها |
| **بانتظار التحصيل** | رُفعت الفاتورة على إنفاذ | تسجيل التحويل · متابعة |
| **محصّلة** | وُثّق التحويل | عرض فقط |
| **متوقفة** | جاهزة ولم تُرفع، أو متعذّرة من المركز | تُستدعى وتُكمل بعد تغيّر حالتها |
| **مستبعدة** | ملغاة أو متعذّرة نهائياً | عرض فقط |

**حالات إنفاذ:** مرفوعة على إنفاذ · بانتظار الفاتورة · ملغاة من إنفاذ · متعذّرة.
ما بعدها يسجّله نظامنا لا إنفاذ.

**التأهّل للفوترة:** عند رفع المعاملة على إنفاذ وتغيّر حالتها إلى «مرفوعة» أو «بانتظار الفاتورة».

**المطابقة** داخل زر «تحديث حالة المعاملة» ولا تظهر إلا للحالتين المؤهِّلتين. يؤكّد فيها الموظف بنود الأتعاب مقابل إنفاذ، ويلزمه إدخال كل ما تستحقه الشركة (المكتب الهندسي والمفاتيح) حسب مؤشري الاستحقاق.

**الفوترة على المعاملات المختارة لا على أمر العمل.** التجميع تحت أمر العمل للعرض فقط تسهيلاً، مع إمكانية الطي والتوسيع. أغلب أوامر العمل معاملة واحدة.

**التحصيل على الفاتورة:** تحويل واحد يُقفل كل معاملاتها. تبويب «بانتظار التحصيل» يجمع بالفاتورة لا بأمر العمل.

**تحققات:** تفرّد رقم الفاتورة · تحذير سنة سابقة (لا يمنع) · مرفق الفاتورة إلزامي · تنبيه اختلاف مبلغ التحويل عن الإجمالي (لا يمنع).

## ٤. دورة التكاليف — صرف المستحقات

### 4.1 المورّد (المكتب الهندسي) — أربع خطوات

```
مسير مُعد (لدى المالية) → أُرسل للمكتب → فاتورة واردة (مطابقة وقيد) → أمر صرف → مدفوع
                                              ↓ إعادة للتصحيح
                                        (تُؤرشف ويعود للانتظار)
```

1. **المسيرات تُنشأ آلياً في نهاية كل شهر مالي** — مسير واحد لكل مكتب يضم معاملاته الجاهزة. لا تكرار لنفس المكتب والشهر.
2. **يبقى محتجزاً لدى المالية** حتى قرار الصرف — لئلا يسبق تاريخ الفاتورة تاريخ الصرف.
3. عند الصرف: **تحويل المسير للمكتب** ليُصدر فاتورة مطابقة.
4. **المكتب يرفع الفاتورة** على المسير من بوابته: رقم + تاريخ + نسخة PDF إلزامية. **القيمة مقفلة على المسير.**
5. **المالية تُقر المطابقة** (الفاتورة للقراءة فقط) وتُصدر أمر الصرف — أو **تُعيد للتصحيح** بسبب إلزامي، فتُؤرشف الفاتورة المرفوضة ويظهر السبب للمكتب.
6. **توثيق الصرف:** سند صرف (فريد) + مرجع تحويل + إيصال — الثلاثة إلزامية.

### 4.2 الفرد (المقيّم · المراجع الحكومي · منفّذ المهمة) — ثلاث خطوات

```
أمر صرف صادر → توثيق الصرف → مدفوع
```

لا فاتورة ولا مسير. أمر الصرف نفسه يجمع البنود في دفعة واحدة بتحويل واحد وإيصال واحد.

### 4.3 تبويبات حساب المستحق

| التبويب | المحتوى |
|---|---|
| **المستحقات** | البنود غير المُدرجة في مستند — العدّاد يحصر **الجاهز للصرف** فقط |
| **مسيرات وأوامر صرف** | المستندات قيد الإجراء (والملغاة كسجل، بلا احتساب) |
| **مدفوعة** | المستندات المنتهية للمطابقة |
| **مستبعدة** | ملغاة أو مخسومة بالكامل — سُوّيت قبل الاستحقاق |

### 4.4 ضوابط
- **الضريبة 15٪** على أتعاب الموردين (منشآت مسجّلة)، والأفراد بلا ضريبة. المطابقة على **الإجمالي**.
- **الصافي صفر لا يدخل مستند صرف** — يُسوّى قبل الاستحقاق ولا يصل المالية.
- **إقفال البنود بالمعرّف لا بالصك** — منعاً للإقفال الخاطئ.
- **تفرّد رقم سند الصرف** — منعاً للدفع المزدوج.
- **إلغاء المستند** قبل الدفع يُرجع بنوده مستحقات، ويبقى المستند «ملغى» كسجل بلا ادّعاء سداد.
- **عمر الاستحقاق** ظاهر (يحمرّ بعد 30 يوماً)، والأقدم أولاً، والجاهز قبل الموقوف.
- **سجل الإجراءات** بالفاعل والتاريخ لكل مستند.

## ٥. شاشة مهامي

تجمع كل ما يتطلب إجراءً من المالية في قائمة واحدة، وكل صف ينقل إلى موضعه بالضبط:

**من الإيرادات:** تحديث حالة/مطابقة · تسجيل الفاتورة · تسجيل التحويل (مع عمر المستحق).
**من التكاليف:** تحويل المسير للمكتب · مطابقة فاتورة المورّد · توثيق الصرف · إصدار أمر صرف للأفراد (مجمَّعاً لكل مستحق).

## ٦. قرارات مرفوضة عن قصد

توثيقها يمنع إعادة اقتراحها:

| القرار | سبب الرفض |
|---|---|
| قاعدة الدفع بعد التحصيل من إنفاذ | أُلغيت بقرار المستخدم — الاستحقاق بالتسليم والقبول |
| اعتماد ثانٍ قبل الصرف | يُدخل شخصاً ثالثاً في دورة هي للمالية وحدها؛ سجل الإجراءات يكفي للمساءلة |
| مسير صرف للأفراد | لا فائدة — لا فاتورة تُطابَق، وأمر الصرف يجمع بنفسه |
| «مُفوترة على إنفاذ» كحالة | مكرِّرة — رفع الفاتورة يُسجَّل عندنا فتنتقل لبانتظار التحصيل |
| فوترة على مستوى أمر العمل | الفاتورة على المعاملات المختارة؛ التجميع للعرض فقط |
| إقفال بتسوية داخل شاشة المالية | التسوية تقع قبل الاستحقاق ولا تصل المالية |

## ٧. طريقة العمل لكل إجراء جديد

1. **مشروع تصميم جديد** باسم الإجراء.
2. انقل إليه: شاشة المالية المعنية + الشاشات المتأثرة + **هذا المستند**.
3. **المصدر كورسر لا البروتوتايب** — الصق الشاشة الفعلية أو صِفها.
4. صمّم وراجع وارفع، ثم **حدّث هذا المستند** من واقع ما طُبِّق.
5. المشروع ينتهي بالتسليم فلا يتقادم.
