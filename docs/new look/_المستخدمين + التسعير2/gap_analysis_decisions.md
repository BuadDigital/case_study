## ١. القرارات التسعة — محسومة كلها

### ق١ — مدير النظام
**`cdo` هو مدير النظام.** لا دور جديد — يُغيَّر مسمى العرض فقط إلى «مدير النظام». الصلاحيات الـ ١٢ والصفحات الـ ٢٨ تبقى كما هي.

### ق٢ — أسماء الأدوار
**تُعتمد أسماء الكود** (`case-specialist` · `real-estate-appraiser` · `financial-officer` ...). لا إعادة تسمية. يُضاف جدول مطابقة في رأس `users_module_spec.md`:

| المواصفة (v3) | الكود المعتمد |
|---|---|
| `case_study_specialist` | `case-specialist` |
| `real_estate_evaluator` | `real-estate-appraiser` |
| `finance` | `financial-officer` |
| `section_supervisor` | `section-supervisor` |
| `field_inspector` | `field-inspector` |
| `government_reviewer` | `government-reviewer` |
| `engineering_office` | `engineering-office` |
| مدير النظام | `cdo` |

### ق٣ — الدخول بالجوال
**التحول الآن ضمن بناء OTP** — لا مرحلة انتقالية مزدوجة.
- `mobile` يصبح معرّف الدخول · فريد · إلزامي
- **مدير النظام يعبّئ جوالات المستخدمين الأحد عشر** في البذرة قبل التفعيل
- شاشة الدخول تُحوَّل من البريد إلى الجوال في نفس التسليم

### ق٤ — سجلات أتعاب المفاتيح التاريخية
- `KeyReceiptFeeCharge` القائمة **تبقى للقراءة** — قاعدة «لا حذف نهائي»
- بند الإيراد في `FinancialReportService` يبقى **للسجلات التاريخية فقط**
- **لا سجل جديد يُنشأ** — يُستبدل الختم بعلم غير مالي واضح (مؤشر استحقاق)
- المعالجة الكاملة ضمن **دورة الإيرادات المؤجلة** (جلسة تصميم مستقلة)

### ق٥ — الحالات الست الزائدة
**تُبقى كامتداد معتمد** (`draft` · `sup-review` · `deferred` · `disb-req` · `returned` · `inquiry`) بثلاثة شروط:
1. مسميات عربية واضحة للطرف في تبويبه المالي (`returned` = «مُعاد — نقص مستند» · `inquiry` = «استفسار معلّق»)
2. **مسار الموظف يتخطى `sup-review` و`office-review` و`disputed`** — الخصم المعتمد ⇒ جاهز مباشرة مع إبلاغ (قرار «يُبلَّغ فقط»)
3. كل انتقال ⇒ `audit_log`

خريطة الحالات المعتمدة:

| المواصفة | الكود |
|---|---|
| `ready_for_billing` | `at-finance` |
| `pending_approval` | `office-review` |
| `dispute` | `disputed` |
| `included` | `in-statement` |
| `paid` | `disbursed` |
| `suspended` | **حالة جديدة تُبنى** — مستقلة عن `ExcludedFromBatch` |

### ق٦ — الكشوف
**آلية كشوف واحدة تُعمَّم** للمعاين والمراجع — يُرفع قيد `engineering-survey` الحرفي.
- مسار `DisbursementBatch` يُدمج أو يُتقاعد لصالح الكشوف — لا مساران متوازيان
- عدّاد مرجعي واحد `FN-CS-YYMMDD-NNN` للجميع (النمط الذرّي القائم)
- الإقفال بفاتورة + إيصال يبقى شرطاً موحداً

### ق٧ — بند لكل صك
**المسار أ: البنية الآن، التفكيك مؤجل.**
- `InspectorFeeLedger`: معرّف `Id` مستقل جديد + أعمدة `TransactionId` · `DeedId` · `UserId` + **فهرس فريد** على الثلاثية · `WorkflowTaskId` يصبح عموداً عادياً
- تفكيك مهام مستوى الـ PO إلى صف لكل عقار: **مؤجَّل** — الصكوك المجمعة نادرة
- **قاعدة مؤقتة تُعلن للمالية:** المعاملة المجمعة تُسعَّر حالياً بأكبر مساحة، وتُصحَّح يدوياً بأداة الخصم/التعديل حتى إشعار

### ق٨ — بذرة المعاين المتعاون
**٤٠٠/٥٠٠ تُحذف** — قاعدة «لا بذرة ولا احتياطي» تشملها بلا استثناء.

### ق٩ — صلاحية «تأكيد التحصيل»
**تُصحَّح الآن** رغم انتمائها لدورة الإيرادات — خطأ صلاحية حي: يُستبدل شرط `submit-party-work` على endpoint `fee-collected` بـ `manage-financial`.

## ٢. اعتماد خطة العمل §٦

**الترتيب معتمد كما ورد: أ → ب → ج → د → هـ** مع الملاحظات:

| البند | ملاحظة الاعتماد |
|---|---|
| أ١ HTTPS + تعطيل `login-username` إنتاجاً | معتمد — **الأول مطلقاً** · التحقق من التعطيل يُضاف كاختبار |
| أ٢ `audit_log` عام | معتمد — تعميم نمط `CourtAuditLog` |
| أ٣ توحيد المستخدم | معتمد — يشمل عمود `role` الصريح بدل مطابقة نص المسمى (المفاجأة ٢ في التقرير) |
| أ٤ `PATCH /api/users/{id}` | معتمد |
| أ٥ طبقة حفظ واحدة | معتمد — شرط المرحلة ٢ |
| ب١–ب٧ التسعير | معتمدة كلها · ب١ يشمل جعل `NormalizeTiers([])` **يفشل لا يبذر** (أخطر نقطة في التقرير) |

| ج٢ `supervising_department` | معتمد — الإشراف يتبع المعاملة (قرار هيكلي ٩ في v3) |
| ج٣–ج٩ | معتمدة · ج٩ وفق ق٦ (تعميم الكشوف) |

| هـ الصور | معتمد — الترتيب الإلزامي: **EXIF ← تحويل HEIC ← تصغير ١٦٠٠/٨٠٪/سقف ١MB ← وسم (بالصك والإحداثيات والوقت) ← رفع** · المستندات بلا ضغط |

**إضافتان على الخطة:**
1. **إصلاح إعادة حساب المهلة** عند تحديث ترويسة أمر العمل (`WorkOrderService.cs:528-531`) — الجارية تحتفظ بمهلتها المحسوبة عند الاستلام (المفاجأة ٥). تُنقل من الملاحظات إلى بند صريح في (أ)
2. **تأمين `OperationsTaskSequence`** تحت التزامن بنمط عدّاد الكشوف الذرّي — يُنفذ مع ج٩

## ٣. ثوابت تُختبر لا تُفترض

تُضاف اختبارات صريحة لكل قاعدة صارمة خُرقت أو كادت:
1. `disputed` لا يظهر في أي استجابة مالية (استعلامات + إحصاءات)
2. جدول فارغ ⇒ خطأ صريح، لا بذرة
3. لا سعر ⇒ لا بند، في كل الفئات
4. مسار الموظف لا يدخل `office-review` / `disputed` أبداً
5. تعديل ترويسة أمر عمل لا يغيّر `DueDateAt` القائم
6. `login-username` يرد 404 في بيئة الإنتاج
7. الجدول المرتبط بأطراف يرفض `SaveAsync` — النسخ وإعادة الربط ذرّيان
