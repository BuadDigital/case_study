> ملف موجّه للمطور في Cursor.
> يغطي: المصادقة، الجلسات، العمل الميداني دون اتصال، المزامنة، معالجة الصور.
> **ملف مرتبط:** `users_module_spec.md` (بيانات المستخدم وشاشة التسجيل).
> جميع القواعد أدناه **معتمدة** من صاحب المنتج.

## ١. المصادقة

### ١.١ الأساس

| البند | القرار |
|---|---|
| معرّف الدخول | **رقم الجوال** |
| المصادقة الأساسية | كلمة مرور + رمز تحقق (OTP) |
| المصادقة البديلة | البصمة / التعرف على الوجه |
| قناة الرمز | **رسالة نصية أو بريد إلكتروني — المستخدم يختار** |

### قناتا التحقق

| القناة | ملاحظة |
|---|---|
| رسالة نصية | الافتراضية |
| بريد إلكتروني | قناة احتياطية — تُستخدم عند تعطل اشتراك الرسائل أو ضعف تغطية الشبكة |

**الخيار متاح لجميع الأدوار — داخليين وخارجيين.**

> ⚠️ البريد قناة تحقق، فهو بحساسية رقم الجوال.
> **تغييره صلاحية مدير النظام حصراً** — للداخلي (بريد الشركة) والخارجي (بريد شخصي) على السواء.
> المستخدم لا يغيّر بريده بنفسه إطلاقاً.

**النتيجة:** ثلاثة مسارات دخول مستقلة (رسالة · بريد · بصمة) — لا نقطة فشل واحدة.

### ١.٢ متى يُطلب OTP

| الحالة | المطلوب |
|---|---|
| أول دخول من جهاز جديد | جوال + كلمة مرور + **OTP** |
| جهاز معروف · آخر تحقق < ٤ ساعات | جوال + كلمة مرور |
| جهاز معروف · مضى > ٤ ساعات خمول | جوال + كلمة مرور + **OTP** |
| جهاز مفعّل بالبصمة | **بصمة فقط** |
| جهاز بالبصمة · مضى ٣٠ يوماً | بصمة + **OTP** (إعادة تحقق دورية) |

> «٤ ساعات» تُحسب من **آخر نشاط**، لا من لحظة الدخول.
> يتطلب تخزين بصمة جهاز (device fingerprint) — بدونها تفقد القاعدة معناها.

### ١.٣ حدود المحاولات

| البند | القيمة |
|---|---|
| محاولات إدخال الرمز | ٥ → يُبطل الرمز ويُطلب جديد |
| طلب رمز جديد | ٣ مرات/ساعة لنفس الرقم |
| بعد التجاوز | إيقاف مؤقت **١٥ دقيقة** + إشعار لمدير النظام |
| محاولات كلمة المرور | ٥ → قفل الحساب حتى يفكّه مدير النظام |
| صلاحية الرمز | ٥ دقائق |

## ٢. الدخول بالبصمة (WebAuthn / Passkeys)

### ٢.١ التقنية

معيار **WebAuthn** المدمج في المتصفحات — لا يتطلب تطبيقاً أصلياً.

| المتصفح | الدعم |
|---|---|
| Safari / iOS | Face ID · Touch ID |
| Chrome / Android | البصمة · الوجه |
| Chrome · Edge / سطح المكتب | Windows Hello · بصمة اللابتوب |

> ⚠️ **شرط إلزامي: HTTPS.** لا يعمل WebAuthn على `http://` ولا على IP بلا شهادة.
> يجب مراعاته في إعداد الخادم منذ الآن.

### ٢.٢ القواعد

| البند | القرار |
|---|---|
| المتاحة لـ | جميع الأدوار |
| الإلزام | **اختيارية** — تُعرض بعد أول دخول ناجح |
| عدد الأجهزة | حتى **٣** لكل مستخدم |
| ما يُخزَّن في الخادم | مفتاح تشفير عام + معرّف الجهاز فقط |
| البيانات الحيوية | **لا تغادر الجهاز إطلاقاً** — لا مسؤولية قانونية على الشركة |
| فقدان الجهاز | مدير النظام: «إلغاء أجهزة هذا المستخدم» |
| إعادة تحقق دورية | OTP كل ٣٠ يوماً |

**فائدة إضافية:** البصمة مسار بديل عند تعطل مزوّد الرسائل — تمنع توقف النظام بالكامل.

## ٣. العمل دون اتصال

### ٣.١ النطاق

| البند | القرار |
|---|---|
| الأدوار المشمولة | **المعاين الميداني · المراجع الحكومي** |
| الوظائف المتاحة | **نماذج الإدخال فقط** — لا تصفح عام للنظام |

### ٣.٢ التنزيل المسبق (Pre-fetch)

تلقائي عند فتح النظام والمستخدم متصل:

| النوع | التنزيل |
|---|---|
| بيانات المعاملات **النشطة** المسندة للمستخدم | ✅ تلقائي |
| المستندات الأساسية (الصك · قرار الإسناد · رخصة البناء · الكروكي · محضر التجزئة · خطاب التمكين) | ✅ تلقائي |
| الصور التوثيقية (معاينات سابقة · صور ظروف) | ❌ عند الطلب فقط |

**السبب:** المعاين يطابق ما يراه ميدانياً بالصك — لا يستطيع الإجابة على أسئلة المطابقة دون فتح المستند.

### ٣.٣ سقف الجلسة دون اتصال

```
٠:٠٠  بدء العمل دون اتصال
١:٠٠  تنبيه
٢:٠٠  تنبيه
٣:٠٠  قفل كامل
```

| البند | القرار |
|---|---|
| السقف | **٣ ساعات** |
| التنبيه | كل ساعة |
| عند الانتهاء | **قفل كامل** — لا فترة سماح، لا وضع قراءة |
| البيانات | محفوظة مشفّرة · تُزامن عند الدخول التالي |

**المبرر التشغيلي:** المعاين لا يبتعد عن نطاق التغطية أكثر من ٣ ساعات.

### ٣.٤ التخزين المحلي

| البند | القرار |
|---|---|
| التشفير | **إلزامي** لجميع الأدوار |
| الحفظ | لحظي أثناء الإدخال — لا يعتمد على حفظ يدوي |
| الحذف | بعد تأكيد رفع **كل عنصر** على حدة |
| مستخدم معطّل | يُرفض دخوله ويُؤمر التطبيق بمسح التخزين المحلي عند أول اتصال |

### ٣.٥ طبقة الكتابة الواحدة

كل كتابة HTTP من الواجهة (`POST` · `PUT` · `PATCH` · `DELETE`) تمر عبر
`repositoryFetch` في:

`packages/api-client/src/write-repository.ts`

الطبقة شفافة اليوم عند الاتصال، وتقبل `ApiWriteInterceptor` واحداً تستطيع مرحلة العمل
دون اتصال أن تستخدمه لاعتراض الكتابة وحفظها في IndexedDB ثم إعادتها. القراءات لا تمر
بالاعتراض. لا يجوز لمكوّن أو مكتبة واجهة استخدام `fetch` مباشر لعملية كتابة؛ اختبار
`write-repository.test.ts` يفحص `apps` و`packages/api-client/src` ويمنع رجوع هذا
التشتت.

الاستثناء المقصود: تفضيلات العرض المحلية مثل الثيم والتبويب المفضل ليست عمليات أعمال
ولا تُزامن مع الخادم، لذلك تبقى في `localStorage`.

## ٤. المزامنة

### ٤.١ المبدأ

**تلقائية وصامتة.** المستخدم لا يقرر، لا يُسأل، ولا يعلن حالة الاتصال.

```
المستخدم يحفظ
      ↓
النظام يحاول الإرسال فوراً
      ↓
  ┌───┴───┐
 نجح     فشل
  ↓       ↓
مسجّل   معلّق + إعادة محاولة تلقائية
```

### ٤.٢ واجهة المستخدم

أيقونة واحدة في شريط النظام العلوي، بجانب اسم المستخدم — **موضع ثابت**:

| الأيقونة | الحالة |
|---|---|
| ✅ رمادية باهتة | تمت المزامنة |
| 🕓 دوّارة | جارية |
| ⚠️ حمراء | فشلت — النظام يعيد المحاولة |

عند الضغط عليها (اختياري): قائمة بما لم يُزامن.

**ممنوع:**
- نوافذ منبثقة عن حالة الاتصال
- رسالة «تعذر الاتصال»
- زر «مزامنة الآن»
- سؤال «هل تريد الحفظ محلياً؟»

**الاستثناء الوحيد** — عند تسجيل الخروج أو إغلاق النظام وهناك عناصر لم تُرفع:
> «هناك N عناصر لم تُرفع بعد. أبقِ النظام مفتوحاً حتى تكتمل.»

### ٤.٣ المزامنة الجزئية

لا يُعتبر العنصر مزامَناً إلا بتأكيد رفع **كل مكوناته**: البيانات النصية + الصور + المستندات.

فشل أي مكوّن ← المعاملة تبقى معلّقة · النسخة المحلية **لا تُحذف**.

### ٤.٤ قاعدة التعارض

**المبدأ: كل حقل له مصدر أصيل واحد. المزامنة دمج لا استبدال.**

| مجموعة الحقول | المصدر الأصيل | عند المزامنة |
|---|---|---|
| بيانات التعميد · الصك · المالك · المحكمة والدائرة · رقم الطلب | الأخصائي / البورصة | **الخادم يسود** |
| إجابات المعاينة · الصور · الإحداثيات · مطابقة المفاتيح | المعاين | **الجهاز يسود** |
| بيانات الظرف والمفاتيح | المراجع | **الجهاز يسود** |

**حالة خاصة:** تغيّرت بيانات مصدرية بعد تنزيل المعاين لها
→ تُحدَّث + **تنبيه للأخصائي**: «تغيّرت بيانات مصدرية بعد تنزيل المعاين — راجع الإجابات».

## ٥. معالجة الصور

### ٥.١ التسلسل الإلزامي

```
التقاط الصورة (أي صيغة)
      ↓
استخراج EXIF: الإحداثيات + وقت التصوير   ← قبل الضغط، وإلا ضاعت نهائياً
      ↓
تحويل + تصغير + ضغط  →  JPEG
      ↓
طبع الشريط التوثيقي   ← بعد التصغير، وإلا صغر النص
      ↓
تخزين محلي + رفع
```

### ٥.٢ معايير الضغط

| البند | القيمة |
|---|---|
| الصيغة المخرجة | **JPEG دائماً** — تحويل تلقائي من HEIC وغيرها |
| الضلع الأطول | ١٦٠٠ بكسل |
| الجودة | ٨٠٪ |
| المتوسط الناتج | ~٤٠٠ كيلوبايت |
| السقف الأعلى | ١ ميجابايت |
| مكان المعالجة | **داخل الجهاز قبل الرفع** — لا يستهلك رصيد المعاين |
| النسخة الأصلية | **لا تُحفظ** |
| المستندات | **بلا ضغط** — الضغط يُتلف نص الصك |

> ⚠️ صور iPhone تأتي بصيغة HEIC التي لا تعرضها كل الأنظمة.
> التحويل يتم برمجياً — **لا يُعتمد على تغيير المستخدم لإعدادات جهازه**.

### ٥.٣ الشريط التوثيقي المطبوع

شريط داكن شبه شفاف أسفل الصورة، غير قابل للإزالة:

```
▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓
صك ٧١٥٧٠٢٠٠٣٥٧٧
21.800029, 39.093016
٢٠٢٦/٠٧/٢٨ — ١٠:٣٢ ص
```

| العنصر | الحالة |
|---|---|
| رقم الصك | ✅ يُطبع |
| الإحداثيات | ✅ تُطبع |
| التاريخ والوقت | ✅ يُطبعان |
| اسم الحي | ❌ **لا يُطبع** — يُصحَّح لاحقاً ويظهر في التقرير |

**سبب استبعاد الحي:** الصورة تُلتقط قبل إكمال النموذج، فسيُطبع الحي القديم من الصك — أي المعلومة التي قد تكون خاطئة. الصورة تحمل ما لا يوجد إلا في لحظتها.

### ٥.٤ التحقق من الموقع

| الحالة | السلوك |
|---|---|
| إحداثيات متوفرة | تُحفظ + تُقارن بموقع العقار |
| المسافة > ٥٠٠ متر | وسم **«خارج نطاق العقار»** |
| لا إحداثيات (GPS مطفأ) | وسم **«موقع غير متاح»** |
| في كل الحالات | **الصورة تُرفع — لا منع إطلاقاً** |

**المستفيد من الوسم: الأخصائي عند المراجعة** — لا يُعرض للمعاين ولا يوقف عمله.
المنع خطأ لأن GPS قد يكون معطّلاً، أو الانحراف داخل مبنى خرساني، أو إحداثيات العقار نفسها خاطئة.

### ٥.٥ ما يُخزَّن مع كل صورة

| الحقل | المصدر |
|---|---|
| خط العرض / الطول | EXIF |
| وقت التصوير الفعلي | EXIF |
| المسافة عن موقع العقار | يحسبها النظام |
| حالة الوسم | مطابق / خارج النطاق / غير متاح |

## ٦. الظروف والمفاتيح دون اتصال

بيئة المحاكم سيئة الاتصال، والتسجيل المتأخر يفقد الدقة.

### ٦.١ المسار

```
داخل المحكمة (دون اتصال)
   تسجيل الظرف · رقم الطلب · عدد المفاتيح المكتوب والفعلي
   صورة الظرف · خطاب الاستلام
        ↓
   الحالة: «معلّق»  → لا بند أتعاب · لا إشعارات · لا يظهر للمالية
        ↓
   ──── عودة الاتصال: مزامنة تلقائية ────
        ↓
   مزامنة كاملة (بيانات + صورة + خطاب)
        ↓
   الحالة: «مسجّل» → يُولَّد بند الأتعاب
```

### ٦.٢ القواعد

| البند | القرار |
|---|---|
| التسجيل دون اتصال | **مسموح** |
| توليد بند الأتعاب | بعد **مزامنة كاملة** فقط — الصورة والخطاب إثبات مالي |
| المزامنة الجزئية | لا تولّد أتعاباً · الظرف يبقى معلّقاً |
| تنبيه اختلاف عدد المفاتيح | يعمل **محلياً** (مقارنة رقمين) — يُصحَّح الخطاب قبل مغادرة المحكمة |

### ٦.٣ لوحة المتابعة

| البند | القرار |
|---|---|
| اللوحة | «ظروف معلّقة لم تُزامن» |
| عتبة التنبيه | **ساعتان** من لحظة التسجيل |
| المستقبِل | **مشرف دراسة الحالة** (المراجع يعمل في عملياته) |
| المستخدم الميداني | لا يُنبَّه — أيقونة المزامنة فقط |

**المبرر:** الاتصال متوفر خارج المحكمة، فأي تعليق يتجاوز ساعتين ليس مشكلة شبكة بل عطل حقيقي (جهاز مطفأ · إغلاق النظام قبل اكتمال الرفع · فشل رفع ملف · خطأ خادم).
اللوحة **أداة كشف خلل** لا أداة تشغيل — في الوضع الطبيعي تكون فارغة.
