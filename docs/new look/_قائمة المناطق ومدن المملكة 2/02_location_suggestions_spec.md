# المسميات المبدئية — المدن والأحياء (v1)

**الغرض:** معالجة الحالة التي لا يجد فيها المستخدم اسم المدينة أو الحي في القائمة، دون إيقاف العمل ودون تلويث البيانات بمسميات مكررة.

**المبدأ:** الإدخال متاح فوراً — والضبط يحدث في طبقتين: منع التكرار عند الإدخال، ثم مراجعة مسؤول النظام.

**النطاق:** المدن والأحياء بنفس المسار.

---

## 1. الجداول

### `cities` — حقول مضافة على المواصفة السابقة

| الحقل | النوع | ملاحظات |
|---|---|---|
| `status` | ENUM | `approved` \| `pending` \| `merged` — كل السجلات المستوردة من المصدر الرسمي = `approved` |
| `raw_input` | VARCHAR(150) NULL | النص كما كتبه المستخدم — يبقى بلا تعديل حتى بعد تصحيح `name_ar` |
| `created_by` | INT FK → `users.id` NULL | فارغ للسجلات الرسمية |
| `created_at` | TIMESTAMP | |
| `reviewed_by` | INT FK → `users.id` NULL | |
| `reviewed_at` | TIMESTAMP NULL | |
| `merged_into` | INT FK → `cities.id` NULL | يُملأ عند الدمج |
| `usage_count` | INT DEFAULT 0 | عدد الصفقات المرتبطة — للفرز في طابور المراجعة |

### `districts` — جدول جديد (الأحياء)

| الحقل | النوع | ملاحظات |
|---|---|---|
| `id` | INT PK | تسلسلي |
| `city_id` | INT FK → `cities.id` | إلزامي — لا يوجد حي بلا مدينة |
| `name_ar` | VARCHAR(150) | |
| `name_search` | VARCHAR(150) INDEX | مُطبَّع (§4) |
| `status` | ENUM | `approved` \| `pending` \| `merged` |
| `raw_input` | VARCHAR(150) NULL | |
| `created_by` / `created_at` / `reviewed_by` / `reviewed_at` | | نفس `cities` |
| `merged_into` | INT FK → `districts.id` NULL | |
| `usage_count` | INT DEFAULT 0 | |
| `is_active` | BOOLEAN DEFAULT true | |

**فهارس:** `INDEX (city_id, status)` · `INDEX (name_search)`

> جدول الأحياء يبدأ **فارغاً** ويُبنى من إدخالات المستخدمين. لا يوجد قيد `UNIQUE` على الاسم — الاعتماد على فحص التكرار في §2.

## 2. مسار الإدخال

### الخطوة 1 — البحث قبل الإضافة

المستخدم يكتب في حقل البحث ← النظام يطابق بـ `name_search` على:
- كل مدن المنطقة المختارة (للمدينة)
- كل أحياء المدينة المختارة (للحي)

المطابقة تشمل: تطابق كامل، بادئة، واحتواء. النتائج المعتمدة أولاً ثم المبدئية.

### الخطوة 2 — لا توجد نتيجة

يظهر خيار: **«إضافة "{النص}" كاسم جديد»**

### الخطوة 3 — فحص التكرار الإلزامي (قبل الحفظ)

عند الضغط على الإضافة يُشغَّل فحص تقارب على النص المُطبَّع، ويُعرض للمستخدم:

> **مسميات مشابهة موجودة — هل تقصد أحدها؟**
> · الصواري ✔ معتمد
> · الصوارى ✔ معتمد
> [ استخدام المحدد ] [ لا، أضف الاسم الجديد ]

هذه الشاشة إلزامية ولا تُتخطى إذا وُجد تقارب. **معظم أخطاء الهمزة والتاء المربوطة تُمنع هنا، لا في طابور المراجعة.**

### الخطوة 4 — الحفظ والاستخدام الفوري

- يُنشأ السجل بـ `status = pending`
- يُستخدم في الصفقة **فوراً** — لا انتظار للاعتماد
- **إذا كان الاسم المُطبَّع مطابقاً لسجل `pending` قائم في نفس النطاق: يُربط بالسجل القائم ولا يُنشأ سجل جديد** (`usage_count++`)
- يُنشأ إشعار لمسؤول النظام

### الخطوة 5 — الوسم الظاهر

الاسم المبدئي يظهر بشارة مميزة (وسم "مبدئي") في:
- نموذج بيانات العقار
- تبويب مساعدة الرفع لإنفاذ
- تقارير الصفقة

## 4. تطبيع البحث (`name_search`)

يُطبَّق على المُدخل والمخزون معاً — نفس قواعد ملف المناطق والمدن:

| القاعدة | مثال |
|---|---|
| حذف التشكيل والتطويل | `أُملُج` ← `املج` |
| توحيد الهمزات: أ إ آ ← ا · ؤ ← و · ئ ← ي | `رأس تنورة` ← `راس تنوره` |
| ة ← ه | `الغزالة` ← `الغزاله` |
| ى ← ي | `ليلى` ← `ليلي` |
| حذف بادئات: محافظة / مدينة / مركز / حي | `حي الصواري` ← `الصواري` |
| توحيد المسافات المتعددة | |

## 5. طابور المراجعة

**شاشة:** إدارة النظام ← المسميات المبدئية

**الفرز الافتراضي:** `usage_count` تنازلياً — الاسم المستخدم في صفقات أكثر هو الأرجح صحة، والأعلى أثراً عند الدمج.

**الأعمدة:** الاسم · المنطقة/المدينة · النص الأصلي (`raw_input`) · المُدخِل · التاريخ · عدد الاستخدامات · مسميات مقترحة للدمج

### الإجراءات الثلاثة

| الإجراء | الأثر |
|---|---|
| **اعتماد** | `status` ← `approved` · تسجيل `reviewed_by` و `reviewed_at` |
| **تعديل** | تصحيح `name_ar` وإعادة توليد `name_search` · **نفس السجل ونفس المعرّف** — الصفقات المرتبطة لا تتأثر · `raw_input` يبقى كما هو · ثم `approved` |
| **دمج** | `status` ← `merged` · `merged_into` ← معرّف السجل المستهدف · `is_active` ← `false` · **تحويل كل الصفقات المرتبطة إلى السجل المستهدف** · `usage_count` المستهدف يزيد بالمقدار المحوَّل |

**لا حذف نهائي.** السجل المدموج يبقى ليخدم المراجع التاريخية والتدقيق.

### اقتراح الدمج التلقائي

عند فتح السجل، يعرض النظام المسميات المعتمدة الأقرب في نفس النطاق (تطابق `name_search` أو مسافة تحرير ≤ 2) كخيارات دمج جاهزة.

| القاعدة | الرسالة |
|---|---|

| الحي يتطلب اختيار المدينة أولاً | |
| يُسمح بإضافة حي تحت مدينة `pending` | الاثنان يظهران في الطابور |

---

## 7. التدقيق

- كل إنشاء/اعتماد/تعديل/دمج يُسجَّل في سجل التدقيق مع المستخدم والتاريخ والقيمة قبل وبعد
- `raw_input` لا يُعدَّل ولا يُحذف — النص كما أدخله المستخدم يبقى مرجعاً
- الصفقة تحتفظ بمرجع المعرّف (`city_id` / `district_id`) لا بالنص — لذا التعديل والدمج ينعكسان تلقائياً على كل الصفقات
