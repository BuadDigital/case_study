## ١. نطاق البناء — مرحلتان

> **حدود النطاق المالي:** هذا التوجيه يغطي **المصروفات فقط** (أتعاب وحوافز الأطراف: استحقاق · خصم · اعتراض · كشوف · صرف · تسعيرة).
> **الإيرادات** (فوترة إنفاذ: دراسة الحالة · الرفع · استلام المفاتيح · VAT · التحصيل) **لم تُصمَّم بعد** — القائم منها في الكود (`PoEnfazRevenueLine` وما حوله) **يُترك كما هو دون تعديل** حتى جلسة تصميم مستقلة.

### المرحلة الأولى (تُبنى الآن)

| الوحدة | البنود |
|---|---|
| المستخدمون | التسجيل · الدعوة والتفعيل · قائمة المستخدمين · ملف المستخدم (الأقسام الأربعة) · ملفي الشخصي · التعطيل |
| المصادقة | جوال + كلمة مرور + OTP نصي · حدود المحاولات · قاعدة الأربع ساعات |
| المالية | الاستحقاق التلقائي · دورة الخصم كاملة · البنود · الكشف (توليد واختيار وإقفال) · توثيق الصرف · إيقاف الحوافز على معاملة |
| الأساسات | سجل التدقيق · صلاحيات الحقول على الدور · **HTTPS** · ضغط الصور + استخراج EXIF |

### المرحلة الثانية (مؤجَّلة — لا تُبنى الآن لكن لا تُغلق البنية دونها)

| البند | ملاحظة للبنية |
|---|---|
| العمل دون اتصال + المزامنة | صمّم الحفظ عبر طبقة واحدة (repository) يسهل اعتراضها لاحقاً |
| البصمة WebAuthn | HTTPS جاهز من الآن — شرطها الوحيد |
| البريد كقناة OTP | حقل البريد موجود ومُلزم من الآن |
| تبويب الكشوف بمستنداته في ملف المستخدم | **الكشوف مبنية فعلاً** (`EngineeringBillingStatement`) — يبقى ربط العرض في ملف المستخدم |
| الترحيل الحر | **مبني فعلاً** (`deferred` · `defer-lines`) — لا يُعاد بناؤه |
| إيقاف الحوافز بفترة زمنية | المرحلة الأولى: على معاملة محددة فقط |
| سجل الأعمال (تبويب العرض) | الحدث يُسجَّل من الآن (نفس حدث الاستحقاق) — التبويب لاحقاً |
| تدرج أعمدة قائمة المستخدمين | المرحلة الأولى: الشاشة لمدير النظام والمشرف فقط |
| وسم الإحداثيات (مقارنة الموقع) | الاستخراج والتخزين **الآن** — المقارنة والوسم لاحقاً |
| الشريط المطبوع على الصور | لاحقاً — الاستخراج قبل الضغط الآن يحفظ البيانات |
| تنبيه انتهاء ترخيص المقيم المعتمد | لاحقاً |

**قاعدة عامة:** كل مؤجَّل له عمود/جدول محجوز في الـ schema من الآن. التأجيل في الواجهة والمنطق، لا في قاعدة البيانات.

### §٢أ — نموذج التسعير (مُطابَق مع المبني — pricing-logic.md)

> النظام يحتوي بنية تسعير مبنية فعلاً (`PartyFeePricingTable/Tier/Assignment`).
> **تُعتمد كما هي** مع التعديلات الثلاثة أدناه. مرجع الواقع: `pricing-logic.md`.

**الفئات الثلاث القائمة:**

| الفئة | التسعير | حدث الاستحقاق |
|---|---|---|
| `engineering-survey` | شرائح مساحة (`MaxAreaM2` شامل · الأخيرة مفتوحة) | **قبول الأخصائي للمخرجات** |
| `government-review` | قيمة الزيارة **يحددها الأخصائي عند إنشاء المهمة** | **إكمال مهمة `court_visit`** |
| `field-inspector` | فرد · منشأة | **قبول الأخصائي للمخرجات** |

**البنية القائمة المعتمدة:** جداول متعددة لكل فئة · افتراضي واحد (`IsActive`) · إسناد طرف عبر `Assignment` · المكتب المسند بلا جدول = **لا سعر** (خطأ صريح، لا fallback) · الختم غير الرجعي في السجل المالي.

**التعديلات الثلاثة المطلوبة على المبني (قرارات معتمدة):**

| # | التعديل | يستبدل |
|---|---|---|
| ١ | **حافز الموظف (معاين أو مراجع):** جدول `flat` يديره **المشرف** (`managed_by = supervisor`) · قابل للتفعيل والإيقاف عبر `incentive_suspensions` · التعديل يسري على الجديد فقط | الإدخال اليدوي بصفر من مسؤول العمليات |
| ٢ | **الجدول المرتبط بأطراف لا يُعدَّل:** التفاوض الجديد = جدول جديد (نسخ) + إعادة ربط · تاريخ الاتفاقات محفوظ | `SaveAsync` الذي يعدّل الجدول القائم مباشرة |
| ٣ | **المراجع الحكومي بنمطي المعاين:** موظف ← بلا قيمة زيارة (يشمله نظام الحوافز) · متعاون ← **الأخصائي يحدد قيمة الزيارة عند إنشاء المهمة** (تُقترح قيمة الجدول كافتراضي قابل للتعديل) · البند يُختم عند إكمال المهمة (`CourtVisitFeeCharge`) | الحل الآلي من الجدول وتصنيفه الثابت «متعاون فرد» |
| ٤ | **نظام حوافز عام لجميع الموظفين** على مستوى المعاملة — أي موظف (أخصائي · مراجع · معاين · مقيم) قد يُفعَّل له حافز عبر `has_compensation` + جدول `flat` يديره المشرف + `incentive_suspensions` · لا كود خاص بدور بعينه | حصر الحوافز في المعاين الموظف |

**إغلاق فجوات يقرّها pricing-logic.md §١٣:**

| الفجوة | الإغلاق |
|---|---|
| لا provenance | السجل المالي يحمل `pricing_table_id` الذي حُسب منه |
| لا audit للتسعيرة | كل إنشاء/تعديل/تفعيل/إسناد/حذف جدول ⇒ audit_log |
| لا concurrency على جداول التسعيرة | row-version على الجداول والشرائح والإسنادات |
| فئة غير صالحة تسقط لـ engineering-survey | تُرفض بـ 400 |
| نسخ عابر للفئات من API | يُرفض — `CopyFromTableId` من نفس الفئة فقط |

**أتعاب استلام المفاتيح — خارج التسعيرة كلياً (حُسم):**
- إيراد للشركة من إنفاذ، **يثبت استحقاقه بتسجيل الظرف** (صورة + خطاب = الإثبات المالي)
- **لا ضبط سعري له** — يُحذف حقل `KeyReceiptFeeSar` من جداول التسعير ويُحذف منطق ختمه عند إنشاء الظرف
- **المبلغ تدخله المالية يدوياً ضمن فوترة إنفاذ** — وهي ضمن **دورة الإيرادات غير المصممة بعد**؛ القائم منها يُترك دون تعديل
- تسجيل الظرف يبقى **مؤشر استحقاق** يظهر للمالية عند الفوترة — بلا مبلغ مختوم

**قواعد الشرائح (كما في المبني):** لا فجوات · لا تداخل · الأخيرة مفتوحة (`MaxAreaM2 = null`) · التطبيع عند الحفظ.

**قاعدة القيم — لا بذرة ولا احتياطي:**
- كل قيم البذرة في الكود القائم (٣٥٠ للزيارة والمفاتيح · شرائح ٣٠٠/٤٥٠/٩٠٠/١٥٠٠/٤٠٠٠) **أرقام تجريبية تُحذف** — ليست أسعاراً معتمدة
- **يُلغى منطق الاحتياط** («لا سعر ← ٣٥٠») من كل المسارات
- القاعدة الموحدة لكل الفئات: **لا سعر مضبوط ← لا بند + خطأ صريح** «تعذر تحديد الأتعاب — راجع ضبط الأسعار» (تعميم قاعدة المكتب الهندسي القائمة)
- الجداول تُنشأ **فارغة** والقيم الفعلية يدخلها مدير النظام من شاشة التسعيرة

**حساب الاستحقاق:**
```
حدث الاستحقاق (حسب الفئة أعلاه) → جدول الطرف (المسند وإلا الافتراضي؛ المكتب: المسند حصراً)
   ├─ flat/حقل مبلغ → base_amount
   └─ شرائح → مساحة الأرض من الصك → الشريحة → base_amount
→ ختم المبلغ + pricing_table_id في السجل — لا رجعية
```

**الصكوك المجمعة:** بند مستقل لكل صك بمساحته (per Sakk).

## ٣. آلة حالات البند المالي

**مساران حسب نوع الطرف — هذا أهم منطق في الوحدة:**

```
حدث الاستحقاق: قبول الأخصائي للمخرجات
      │  (يُنشئ البند + سطر سجل الأعمال معاً)
      ▼
   بسعر الجدول بلا خصم؟
      │ نعم ──────────────────────────► ready_for_billing
      │ لا (عليه خصم حدده المشرف)
      ▼
 ┌─────────────────────┬──────────────────────────┐
 │ خارجي (متعاون/مكتب) │ موظف (معاين موظف/مقيم)  │
 ▼                     ▼
 pending_approval      ready_for_billing مباشرة
 │ موافقة → ready      (يُبلَّغ فقط — لا اعتراض
 │ اعتراض → dispute      ولا dispute إطلاقاً)
 │           │ حسم (مشرف↔طرف، قبل المالية دائماً)
 │           ▼
 └────────► ready_for_billing
                │
                ▼  المالية تولّد كشفاً (المرحلة ١: كل الجاهز)
             included (statement_id)
                ▼  إقفال الكشف: رقم فاتورة + إيصال إلزاميان
             paid
```

**قواعد صارمة:**
1. dispute لا يظهر للمالية إطلاقاً — يُستبعد من توليد الكشف على مستوى الاستعلام
2. suspended = true ⇒ يُستبعد من الكشف · يظهر في الملخص ببطاقة «موقوف» خارج المستحق · رفع الإيقاف يعيده ready
3. **الاستحقاق يُنشأ دائماً عند الإنجاز** — إلغاء المعاملة بعد رفع المخرجات لا يمنعه؛ سببٌ يخص الطرف يعالَج بخصم حتى ١٠٠٪ (بند بصفر يبقى مسجلاً بسببه)
4. إعادة العمل للتصحيح: بلا أتعاب جديدة — البند القائم لا يُمس
5. المشرف المخوَّل بالخصم والحسم = مشرف `supervising_department` في البند — لا مشرف قسم المستخدم

### §٤أ — شاشة الإعدادات العامة

شاشة واحدة في السايدبار · **مدير النظام فقط** · لا «ملف شركة» منفصل.

| # | التبويب | المحتوى | النوع |
|---|---|---|---|
| ١ | بيانات الشركة | الاسم · السجل التجاري · الرقم الضريبي · العنوان · التواصل | يُطبع في المخرجات |
| ٢ | المقيم المعتمد | الاسم · رقم الترخيص · تاريخ الإصدار · الانتهاء · فرع التقييم | يُطبع في المخرجات |
| ٣ | الهوية والأصول | الشعار · الترويسة · التذييل · الختم · التوقيع · العلامة المائية | يُطبع في المخرجات |
| ٤ | التسعير | جداول التسعير (ثابت/شرائح) وربط الأطراف بها — انظر §٢أ | ضبط تشغيلي |
| ٥ | الاتصالات | ضبط API الرسائل النصية · قناة البريد | ضبط تشغيلي |
| ٦ | ضبط النظام | المحاكم والدوائر (تنضم كتبويب) · قوائم التعذر · العدّادات المرجعية (عرض فقط) · **معايير المهل (قابلة للتعديل)** | ضبط تشغيلي |

**قواعد:**
1. **تعديل التسعير لا يمس البنود المُنشأة** — `base_amount` مثبّت لحظة الاستحقاق · السعر الجديد للقادم فقط
2. **الأصول البصرية snapshot-at-issuance** — الخطابات القائمة تحتفظ بما طُبعت به (نفس قاعدة خطاب التفويض)
3. **مفتاح API** يُعرض مقنّعاً (••••1234) · audit_log يسجّل «تم التغيير» بلا قيمة
4. كل تعديل في التبويبات ١–٣ ⇒ audit_log (يمس مستندات رسمية)
