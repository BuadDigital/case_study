2) الأعطال التي وُجدت وأُصلحت  (11 عطلاً)

[1] صورة الواجهة لا تُبنى إطلاقاً
    Dockerfile ينسخ apps/mfe-kpi وهو غير موجود، ويتجاهل

[2] المكتبات الأصلية للينكس مفقودة
    package-lock.json مولّد على Windows فلا يحوي إلا نسخ win32.
    فشل next build عند أول ملف CSS بسبب lightningcss.
    الحل: تثبيت نسختَي musl لـ lightningcss و @tailwindcss/oxide بعد npm ci.

[3] صورة البوابة لا تُبنى
    RealEstateEval.Shared.Web يعتمد على Application الذي يعتمد على Domain،
    وكلاهما غير منسوخ في سياق البناء.

[4] هجرة قاعدة بيانات تفشل على أي قاعدة جديدة   ★ الأخطر
    ملف: 20260810090000_CourtVisitPricingFromGovernmentReview.cs
    الهجرة تنقل قيماً من عمود GovernmentReviewFeeSar وتحرس ذلك بـ
    WHERE EXISTS على information_schema. الحارس لا يحمي شيئاً: بوستجرس
    يحلّل أسماء الأعمدة قبل التنفيذ، فالإشارة إلى عمود غير موجود تفشل
    بـ 42703 قبل تقييم الشرط.
    لم تظهر محلياً لأن قواعد المطورين تسبق إعادة التسمية.
    الأثر لو لم تُكتشف: النشر يفشل عند خطوة migrate، والنظام لا يقوم أبداً.
    الحل: نقل العملية إلى DO block وتنفيذها عبر EXECUTE.

[5] nginx يرجّع 502 بعد كل نشر
    nginx يحلّ اسم gateway مرة واحدة عند الإقلاع، وكل نشر يعيد إنشاء
    الحاوية بعنوان IP جديد.
    أُثبت عملياً: بالإعداد القديم HTTP 502 بعد تغيّر العنوان.
    الحل: DNS الداخلي لـ Docker مع متغير في proxy_pass.

[6] صورة الهجرات لا تقلع
    مبنية على dotnet/runtime بينما Infrastructure يحوي كود ASP.NET
    فيرث اعتماداً على Microsoft.AspNetCore.App.
    الحل: البناء على dotnet/aspnet.

[7] خدمات تنهار عند الإقلاع  (failures ثم platform ثم operations)
    بيانات RabbitMQ ممرّرة لخدمتين فقط من تسع، والباقي يفشل في التحقق
    من الإعدادات عند الإقلاع. البوابة تنتظر صحة كل الخدمات، فبقيت
    الحزمة كلها — وnginx معها — لا تقوم.
    الحل: مرساة YAML واحدة تُطبَّق على الخدمات التسع.

[8] كل نداء /api يرجّع 502
    البوابة توجّه إلى 127.0.0.1:516x وهي منافذ التطوير المحلي.
    ملف appsettings.Docker.json فيه العناوين الصحيحة لكنه لا يُحمَّل
    لأن البيئة Production.
    الحل: إنشاء appsettings.Production.json.

[9] الداشبورد يرجّع 500 عند كل تحميل
    ثلاث خدمات فقط تعرف عنوان Redis، والباقي يستخدم الافتراضي
    localhost:6379 — وداخل الحاوية هو الحاوية نفسها.
    reporting أعادت المحاولة حتى فتح قاطع الدائرة.
    الحل: مرساة موحّدة كما في RabbitMQ.

[10] الداشبورد يرجّع 500 مجدداً بعد إصلاح Redis
    reporting تجمّع بياناتها بالاتصال بالبوابة، وعنوانها الافتراضي
    localhost:5160.
    الحل: UpstreamServices__GatewayBaseUrl = http://gateway:5160

[11] الشهادة كانت ستنكسر بعد شهرين رغم نجاح التجديد   ★ مهم
    Docker يحلّ الرابط الرمزي عند إنشاء الحاوية، وLet's Encrypt تكتب
    ملفاً جديداً عند التجديد لا تعدّل القديم.
    أُثبت تجريبياً على السيرفر: تغيير وجهة الرابط والحاوية تُبقي الملف
    القديم.
    الأثر لو لم يُكتشف: التجديد ينجح على القرص وnginx يواصل تقديم شهادة
    منتهية، والموقع يسقط فجأة بعد ثلاثة أشهر.
    الحل: تجديد بأسلوب webroot (بلا إيقاف nginx)، وخطاف بعد التجديد
    ينسخ الشهادة في نفس الملف المربوط ويعيد تحميل nginx.

  /app/docker-compose.prod.yml   الحزمة (يُنسخ من الريبو عند كل نشر)

الحالة والسجلات:
  docker ps --format "{{.Names}}\t{{.Status}}"
  docker logs ree-prod-<الخدمة> --since 10m
  docker logs ree-prod-<الخدمة> 2>&1 | grep -oE '"Exception":"[^\\]{0,200}'

نشر يدوي بدون CI:
  cd /app
  export IMAGE_OWNER=buaddigital
  export TAG=<sha الإصدار>
  docker compose -f docker-compose.prod.yml pull
  docker compose -f docker-compose.prod.yml run --rm migrate
  docker compose -f docker-compose.prod.yml up -d --remove-orphans

  تحذير IMAGE_OWNER الفارغ عند أوامر compose اليدوية طبيعي ولا يضر
  عمليات stop/start/exec — لكنه يفسد pull و up، فصدّر المتغيرين دائماً.

التراجع لإصدار سابق:
  كل إصدار موسوم بـ sha كامل، والصور القديمة محفوظة (docker image prune
  يحذف المعلّقة فقط). للتراجع: نفس أوامر النشر اليدوي بـ TAG قديم.
  لمعرفة الوسوم المتاحة:
    docker images ghcr.io/buaddigital/case_study/gateway --format "{{.Tag}}"

الوصول للمراقبة (غير منشورة على الإنترنت عمداً):
  Grafana وJaeger وRabbitMQ وPrometheus بلا منافذ عامة. للوصول:

  ثم من داخل السيرفر وجّه المنفذ لعنوان الحاوية، أو أضف ports مؤقتاً.
  كلمة مرور Grafana في /app/.env تحت GRAFANA_ADMIN_PASSWORD.

إعادة بذر الحسابات التجريبية (لو أُفرغت القاعدة):
  الإنتاج يرفض البذر بالتصميم، فالطريقة حاوية مؤقتة بوضع Development
  على نفس الشبكة والقاعدة:

    set -a; . /app/.env; set +a
    docker run -d --name ree-seed --network realestate-eval-prod_default \
      -e ASPNETCORE_ENVIRONMENT=Development \
      -e Database__SeedDemoData=true \
      -e Database__MigrateOnStartup=false \
      -e REAL_ESTATE_EVAL_PG_CONNECTION_STRING="Host=postgres;Port=5432;Database=realestate_eval_prod;Username=postgres;Password=$POSTGRES_PASSWORD" \
      -e Jwt__Issuer=RealEstateEval -e Jwt__Audience=RealEstateEval \
      -e Jwt__SigningKey="$JWT_SIGNING_KEY" \
      -e Redis__ConnectionString=redis:6379 \
      -e RabbitMQ__Host=rabbitmq -e RabbitMQ__Port=5672 \
      -e RabbitMQ__UserName="$RABBITMQ_USER" -e RabbitMQ__Password="$RABBITMQ_PASSWORD" \
      ghcr.io/buaddigital/case_study/case-study:<sha>

  انتظر حتى يظهر مستخدمون في القاعدة ثم: docker rm -f ree-seed
  (هذا تجاوز متعمّد لحارس الإنتاج — لا تفعله على قاعدة فيها بيانات حقيقية)

الموقع ساقط — تسلسل التشخيص الذي نفع كل مرة:
  1. docker ps -a  →  أي حاوية Restarting أو Created؟
     "Created" في gateway/frontend/nginx تعني أنها تنتظر خدمة غير سليمة.
  2. docker logs على الحاوية المنهارة، واستخرج الاستثناء لا آخر سطر.
  3. ss -lnt | grep 443  →  هل nginx يستمع أصلاً؟
  4. قارن /app/docker-compose.prod.yml بنسخة الريبو — تشغيل قديم في
     الطابور قد يكون دهسها (حصل فعلاً).

9) مخاطر مفتوحة  (ليست أعطالاً، لكنها ستؤلم لو أُهملت)
-------------------------------------------------------------------------------

★ لا توجد نسخة احتياطية لقاعدة البيانات — الأخطر
  تحققت: لا cron ولا مهام مجدولة ولا أي pg_dump على السيرفر. البيانات
  كلها في قرص Docker واحد اسمه realestate-eval-prod_ree_prod_pgdata.
  لوحة Hetzner تعرض خيار النسخ الاحتياطي للسيرفر كاملاً — تأكد أنه
  مفعّل، لكنه نسخ لصورة السيرفر كله لا استرجاع نقطة زمنية لقاعدة
  البيانات، والاسترجاع يعني إرجاع السيرفر بأكمله للخلف.
  الحل المقترح: مهمة يومية pg_dump مضغوطة تُنقل خارج السيرفر.
  قبل إدخال أي بيانات حقيقية، هذا أول ما يجب إنجازه.

★ الأسرار موجودة في مكان واحد فقط
  /app/.env يحوي كلمة مرور قاعدة البيانات ومفتاح توقيع JWT وكلمة مرور
  Grafana، وكلها وُلّدت عشوائياً ولا توجد نسخة منها في أي مكان آخر.
  لو ضاع السيرفر ضاعت معه — وضياع مفتاح JWT وحده يبطل كل الجلسات.
  خذ نسخة الآن وضعها في مدير كلمات مرور.

  لا توجد تنبيهات
  Prometheus وGrafana يعملان ويجمعان المقاييس، لكن لا قواعد تنبيه ولا
  جهة تُبلَّغ. أي عطل يُكتشف بأن أحداً يفتح الموقع ويجده ساقطاً.

  لا تراجع تلقائي
  مرحلة النشر تتحقق من الصحة وتفشل بوضوح إن ساء شيء، لكنها لا ترجع
  للإصدار السابق تلقائياً — تبقى الحزمة على حالتها حتى تتدخل يدوياً.

  سيرفر واحد
  قاعدة البيانات والتطبيق والإنجرس كلها على جهاز واحد. أي صيانة أو
  عطل عتاد يعني توقفاً كاملاً. مقبول لنظام في طور الدراسة، لا لإنتاج
